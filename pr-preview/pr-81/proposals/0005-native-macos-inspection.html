Native macOS Inspection ​

Summary ​

Inspect a macOS application's windows, views, cells, and layers through Recon's shared ui surface. Separate accessibility queries under ui ax, native visual inspection under ui view, and inspection-access lifecycle under ui session. Connect these representations to existing window capture and targeting, and apply winctl-derived no-focus rules across observation and interaction without changing platform protections.

Motivation ​

Recon's current ui tree observes an accessibility hierarchy. That hierarchy deliberately hides implementation detail: an accessible button need not reveal its cell, surrounding views, backing layers, typography, constraints, or visual-effect material. A screenshot reveals the pixels but not the objects that produced them. An agent investigating a private subclass, native layout, or a SwiftUI application's AppKit realization cannot answer those questions with either observation alone.

The desired subject is a running application's implementation, including applications the investigator did not build. Requiring every target to adopt an SDK would exclude an important part of that work. Conversely, treating all installed applications as injectable would conceal real signing, debugger, sandbox, pointer-authentication, and system-protection boundaries. Researchers need a useful native inspector that makes those distinctions explicit.

The present workaround is to combine Recon's external observations with a separate in-process tool or debugger and manually reconcile process identity, windows, coordinates, and observations. #51 and #44 put that investigation behind Recon's existing targeting, discovery, and error contracts without redefining Accessibility as a native tree.

Domain grounding ​

Established context ​

  • Apple's Accessibility model explicitly permits an app to omit implementation-specific objects such as content views and cells. AX elements and native objects therefore have neither equal membership nor a guaranteed one-to-one relationship.
  • Apple documents NSWindow.windowNumber as an application window-device number, explicitly distinct from the global WindowServer number. kCGWindowNumber identifies the WindowServer window within the user session. A numeric match in one process is therefore not, by itself, a supported identity bridge.
  • NSView.subviews describes actual containment and ordering; the array can change while the application runs. A child's index, class, name, or current frame is not its object identity. frame is in the superview's coordinate system; bounds is in the view's own. A flipped parent prevents a universal “every view frame is bottom-left” interpretation.
  • A view may have a layer, but layer backing and layer hosting differ. CALayer.sublayers is not NSView.subviews. A presentation layer approximates current on-screen animation state; a model-layer read does not.
  • NSLayoutGuide participates in constraints without being a view. NSView.constraints returns constraints held by that view, not every constraint affecting it. Constraint ownership and constrained items are different relationships.
  • NSHostingView is an AppKit bridge that hosts a SwiftUI hierarchy. Walking its AppKit descendants does not recover every SwiftUI View value, modifier, or AttributeGraph relationship.
  • AppKit's thread-safety guidance restricts view operations to the application's main thread. Reading an overridable property executes target code. An Objective-C exception boundary does not recover a deadlocked getter or guarantee recovery from invalid native memory access.
  • Apple's debugger entitlement documentation distinguishes the inspector's debugger rights from the target's get-task-allow entitlement and describes possible administrator authorization. Accessibility permission is not a task port or permission to load code.
  • Hardened Runtime, library validation, and DYLD environment-variable handling impose separate constraints. Loaded libraries inherit the host executable's entitlements. A signable helper or a single disabled protection does not establish that a particular target can be inspected.
  • Maintained injection machinery has separate arm64e concerns. Frida documents macOS debugger authorization, arm64e system-process support fixes, and later pointer-authentication and loader fixes. These establish relevant prior engineering, not compatibility with every macOS 27 target.
  • Apple's CGEvent API distinguishes posting to a process from posting into a general event stream; neither delivery alone nor a successful post proves that a particular control acted. NSRunningApplication.activate is an explicit activation operation. Process targeting, window routing, target-internal responder state, and the user's foreground keyboard focus are distinct concepts.
  • UIKit's UIWindowScene manages one UI instance with one or more windows and its own lifecycle. A scene, window, process, and inspection session are not synonyms. This constrains the future UIKit vocabulary without adding UIKit support to the current AppKit scope.

Relevant constraints and principles ​

An application bundle, running process incarnation, native object, accessibility element, inspection session, and immutable observation have different identities and lifetimes. A bundle can have several processes; a process can have successive sessions; an object can move between parents without becoming another object; an observation survives all of them as historical evidence. Native windows and WindowServer surfaces have distinct identities even when a verified relationship connects them. A session handle, native pointer, AX snapshot path, or window number is not a durable evidence identifier.

Cooperation, target architecture, signing/protection facts, and host security posture are independent dimensions. “Research” describes an explicitly selected access profile on an operator-prepared machine, not a target class, an entitlement, or an assertion that all protections are absent. arm64e is a relevant Apple-silicon target ABI, not Intel/Rosetta support; it cannot be silently excluded from the protected-system-app outcome.

Ontology review: the ui namespace ​

This review uses the primary sources above, the existing CLI's exercised help/schema, and the explicit session and observation contracts below. The namespace arrangement is a product decision informed by that evidence, not a classification prescribed by AppKit or by the current parser.

CONCEPT INVENTORY

  • UI domain and representations: One interface can have accessibility semantics, native visual objects, compositor pixels, and, in a browser, a DOM. These are different representations of overlapping subject matter, not mutually exclusive kinds of applications.
  • Target and scope: The selected bundle/process incarnation identifies the execution target. A window or native root narrows a query within it; neither is the target's identity. Future device/runtime/scene selection adds scope rather than reusing a Mac window number for another concept.
  • Native visual objects: Windows, views, layers, cells, and layout guides are distinct kinds with different relationships. Fonts and layout/appearance properties are observed facets, not children in one universal UI tree.
  • Inspection access: A Recon session is an authenticated, revocable access relationship to a process. Helper residency is a separate process condition; a session is not an application instance, UI scene, open window, or saved investigation.
  • Observation and correlation: An observation is an immutable, time-bounded record of a particular scope/source. A correlation is evidence-backed correspondence between observations, not a new shared object identity or an executable action target.
  • Operation and effects: Read, capture, access-lifecycle, and action requests are different operations. Their permissions, target-code execution, file writes, setup prompts, and possible interference are independent of which namespace contains them.

CONFLATIONS AND FALSE DISTINCTIONS

  • Top-level ax falsely separates Accessibility from the UI domain, while a generic ui tree makes native structure the unqualified meaning of “UI.” Resolve both with explicit sibling representations: ui ax tree and ui view tree. Neither source is a fallback or a more complete version of the other.
  • Treating every native object as a view would conflate view containment, layer containment, cell ownership, and layout relationships. Mark chose ui view as the native visual-inspection family, not an assertion that every returned object is an NSView. Preserve typed nodes, explicit relationships, and separate --kind view|layer traversal; do not splice layers, masks, cells, or guides into view children.
  • Bare ui open/close obscures whether the command changes application/window lifecycle or inspection access. Name the existing access concept with ui session preflight|open|close; closing it does not close a window or quit the app.

IDENTITY / LIFECYCLE AND RELATIONSHIP ISSUES

  • WindowServer IDs, native weak handles, AX observation paths, and observation IDs remain non-interchangeable. Shared targeting means a verified relationship, not a universal UI-node identifier. No title, tree index, frame, or correlation candidate becomes identity.
  • Independent review found that the previous draft nevertheless derived a verified WindowServer selector by matching the native window number within the process inventory. That rule is removed: retain the AppKit device number as source-specific evidence and require a separately justified, live identity bridge before emitting a usable windowId. The bridge is an unresolved approval prerequisite, not permission to reduce the required shared-window workflow to guesses or permanently unmatched results.
  • A native object's handle survives reparenting while the object survives, but an old window-scoped request can become invalid after that move. Session revocation invalidates access/handles while copied observations remain historical evidence and helper code can remain resident.
  • View/layer containment, a layer mask, a control's cell, constraint ownership, and a constraint's referenced item have different cardinalities and traversal rules. A tree command traverses one named containment relation; a node command exposes other relationships as typed references.

CLASSIFICATION, VOCABULARY, AND IMPLEMENTATION LEAKAGE

  • ui names the investigation domain. ax and view identify the representation being queried, not a platform, loader, permission, or promise of observational purity. ui windows, ui screenshot, and ui correlate remain shared operations because they discover scope, capture pixels, or relate sources rather than belonging exclusively to either graph.
  • ui view node reads an allowlisted native visual object with its actual kind; it is not a general object/heap browser. --kind on tree/find chooses view or layer containment, not a cast of every reachable object to that class. Font inventory is derived from observed carriers and inherits their coverage.
  • ui session is this feature's entry point to reusable inspection access, not ownership of the transport by the view walker. Do not force external AX/capture/actions to use a helper, or make future non-UI consumers implement native UI inspection to reuse session identity.
  • Framework, execution environment, access mechanism, and evidence source are independent axes. A Catalyst app can expose UIKit on macOS; an Electron window can expose native hosting structure as well as AX and DOM evidence. The current AppKit query covers only its selected process and native graph, not every renderer/helper process or a recovered DOM. Future platform proposals retain their own capability/identity proof.
  • Namespace membership grants no action or permission. The current ui ax tree and ui view queries request observation; a later AX action remains an explicit action with its own effects. The shared no-focus rule and retained setup exception apply across namespaces, not only to a particular backend.

Quality bar ​

A useful result identifies the exact process and observation interval, preserves native relationships and coordinate spaces, narrows work before expensive reads, distinguishes absence from unavailable data, and never resolves an old handle to a replacement object. Window capture, AX, native structure, and supported UI actions share a target model and no-focus contract even when their mechanisms differ. A successful session proves real target-side execution. A complete feature demonstrates both cooperative and research access; an honest denial on a stock machine is necessary but not a substitute for the latter.

Feasibility observations, not implementation approval ​

A Recon-owned loader was exercised on this host (macOS 27.0.1, build 26A434) against cooperative get-task-allow fixtures, with no Frida. The loader acquires one task control port, independently verifies the target's process incarnation through its TASK_AUDIT_TOKEN (PID plus the val[7] pidversion) before any effect, verifies the target shares this host's dyld shared-cache UUID and slide, then writes a small position-independent bootstrap and a load_context with mach_vm_write, maps it executable with mach_vm_protect, and starts it. The bootstrap calls pthread_create_from_mach_thread and, on the pthread, dlopen + dlsym + the Recon entry symbol. The loader needs no Mach port beyond the task control port and introduces no debugger exception port or additional special port. Observed end to end: an arm64e loader loaded a fixture and ran its entry (a sentinel written to target memory and read back) in an arm64e target (TextEdit's ABI) and in an arm64 target (IINA's ABI); an arm64 loader did the same for an arm64 target. The arm64e path required building the loader arm64e, setting the entry through ARM_UNIFIED_THREAD_STATE, and calling thread_convert_thread_state with THREAD_CONVERT_THREAD_STATE_FROM_SELF so the kernel produces a PAC-signed entry in the target's domain; a non-PAC arm64 loader cannot set a running arm64e thread, so the shipped loader is arm64e. Pre-effect binding was proven: a deliberately wrong audit token is refused before any mach_vm write, and after the fixture execs the retained task port is invalid and a re-attempt is refused with no new effect, so injection cannot land in a replacement incarnation. thread_convert_thread_state and the audit-token identity primitive are the only non-obvious kernel pieces, both documented in XNU (osfmk/mach/thread_act.defs, bsd/kern/kern_proc.c). This is cooperative-fixture evidence; the protected TextEdit/IINA targets additionally require the inspector's debugger entitlement and Mark's approval of the taskgated dialog, now unblocked because the bound loader is proven.

First-party injection was subsequently proven on this prepared research host (SIP disabled by the operator; boot-args amfi_get_out_of_my_way=0x1 -arm64e_preview_abi). The THREAD_SET_STATE EXC_GUARD that kills a bare debugger-entitled injector on a platform binary is a caller-side check, released by signing the inspector with com.apple.private.thread-set-state, which the kernel honors because AMFI signature enforcement is off. With that entitlement plus cs.debugger, the full loader ran against two Apple platform binaries — TextEdit (flags=0x0(none)) and Music (flags=0x12000, hardened runtime and library validation) — each yielding a live NSApp.windows read (window count plus content-view class) with the target left alive. The helper must sit in a path the target's sandbox can read (/Library/Application Support worked; /private/tmp and /Users/Shared were refused). DisableLibraryValidation was not required; amfi_get_out_of_my_way already relaxes both the thread guard (via the honored entitlement) and library validation. This works only because the operator weakened the host; on a stock machine AMFI rejects the fake entitlement and the guard holds, so first-party injection is a research-host capability, not a shippable posture. The earlier revision's assumption — that a debugger entitlement plus a taskgate dialog, with no host weakening, would reach a platform binary — is falsified: that path hits the guard.

A throwaway, background AppKit fixture on this host created two windows. For both, passing an independently enumerated CGWindowID to NSApplication.window(withWindowNumber:) returned the exact held NSWindow, and passing the other's ID did not; an overridden public windowNumber getter did not change the result. Because native inspection runs in-process through the proven loader, the native window identity is the live NSWindow reachable by walking NSApp.windows; the CGWindowID is used only to correlate a caller-supplied WindowServer --window with that live object. The in-process mapping validates that the WindowServer entry's owner PID equals getpid(), resolves the object, and confirms it is in NSApp.windows. The fixture also showed the public limit: a closed-but-retained window and a hidden window are indistinguishable through public CGWindowList metadata, so an ambiguous or non-visible match is reported unavailable rather than guessed, and a deallocated window's old id resolves to nil. This is a validated bridge for visible windows with honest unavailability elsewhere, not an Apple-documented equivalence of the AppKit and WindowServer number domains.

Source-backed value to preserve: AppKitWalker obtains native runtime classes, fonts, materials, geometry and constraints on the main thread. The server snapshots a broad forest before client-side projection, and the walker gathers rich fields even when only a small projection is returned. Its hand-written injector is plain-arm64-specific; its research/arm64e readiness is not implemented. General font inventory, independent layer handles, explicit cell records, and host-side AX correlation are new Recon work, not an already-complete port.

A selected window is therefore not enforced equally by every upstream operation. Recon must not copy a decorative window argument, first-match action selection, or the assumption that a posted event means successful actuation.

It separately tests focus-without-raise and activate-then-restore alternatives; neither belongs to Recon's no-focus path. The fixtures had previously become key, and the lock-boundary results are qualified in the research. This is prior recorded evidence, not a new macOS 27 interaction test or proof for every control/window/toolkit. Current Recon regression checks compare foreground PID and pointer before/after commands; stronger continuous evidence is required to rule out transient focus theft.

Proposed solution ​

Extend ui as Recon's application-interface umbrella, rather than adding a separate native or top-level ax family. Keep ui windows and ui screenshot: WindowServer enumeration and SkyLight capture are not AX queries. Move the existing AX-only ui tree to ui ax tree, and place native tree/node/find/fonts queries under ui view. Name access lifecycle with ui session; keep cross-source correlation at ui correlate. Native and AX graphs remain distinct evidence, but use the same application/instance/window selection, privacy identity, errors, and no-focus rules. The winctl-derived observation and eventual action paths are part of this surface, not a disconnected adapter.

Keep the Rust CLI and existing contract infrastructure; do not require running uitool, winctl, Flexscope, the FLEX GUI, or an external scripting CLI. A Recon-owned helper implements a closed set of inspection operations, not an arbitrary Objective-C/JavaScript execution service. Only operations that need in-process access require a helper. Window enumeration, capture, external AX, and supported out-of-process input must not acquire an injection prerequisite merely because they share ui targeting. The session machinery remains reusable by non-UI consumers without making them implement the view walker.

Use a Recon-owned native loader and inspection helper. Carry one kernel-bound, independently verified process incarnation through every target-side effect; do not port the prior art's unchecked PID lookups or fixed-delay completion assumption. Prove the loader on the required macOS 27 arm64 and arm64e targets before settling its architecture. Frida integration is excluded. A cooperative-only fallback cannot discharge the research-machine requirement.

Detailed design ​

1. Supported targets, access, and command surface ​

The required host and native target matrix is Apple silicon on macOS 27, including compatible arm64e protected-app targets under the research profile. Intel, Rosetta-translated targets, older macOS, UIKit/Catalyst, Simulator, and physical iOS devices are explicitly unsupported by this proposal. That restriction applies only to the new capability, not existing commands.

Use the existing exact application-name, bundle-identifier, or absolute .app-path selector. A running instance is chosen by --pid when needed; ambiguity remains an error. A raw executable path or bare PID does not bypass bundle resolution and ownership checks. A symlink alias must resolve to the same selected bundle rather than changing which copy is inspected.

CommandBehavior

ui view groups native visual inspection, not only objects whose runtime kind is view. node accepts live native window, view, layer, cell, and layout-guide handles and reports the actual kind; it never converts an AX path, WindowServer ID, or observation ID into a native handle. View tree/find and font inventory accept a view or native-window root; layer tree/find accept a native window, view, or layer root. An incompatible live root kind is INVALID_ARGUMENT, not an empty successful tree or an implicit source switch. Omitting a required layer scope is a usage error. The --kind traversal selector does not relabel node kinds or change the meaning of field groups.

ui session preflight reports inspection-access eligibility, not blanket readiness for every UI operation. context retains its existing non-prompting privacy report, and external AX/capture retain their own permission contracts. Session close concerns inspection access only; window closing and application lifecycle remain separate explicit actions.

There is one application/instance selector, not parallel winctl and helper selectors. A supplied session selects its bound process only after the resolved TARGET is verified to be the same bundle at the same location; any supplied --pid must agree. A stale, mismatched, or unreachable session fails explicitly rather than silently inspecting another instance. External commands without --session retain current instance selection. With it, they validate the session through authenticated lifecycle state but do not invoke the native walker or load code.

--window always means the existing WindowServer CGWindowID owned by that selected process. Native tree/find/fonts and correlation resolve it to the matching live native window; no title, largest-window, array-index, or current-frontmost fallback is allowed. Session-bound AX and screenshot commands validate the bound process but retain their existing AX/WindowServer selection paths; they do not require a native-window match. A supplied native --root must still belong to the selected window when both are given; stale or moved roots fail that scope check. Layer/window membership must be established through live relationships, not a remembered location. A native-only window without a usable WindowServer identity is addressable by its native handle, not a fabricated ID. Window IDs and native handles remain different, lifetime-scoped identifiers.

Without a session, ui windows retains its current output. With a session, the existing WindowServer windows array is accompanied by bounded nativeWindows, session/provenance, and coverage metadata. Native records include their handles, child-window/sheet relationships, and the source-specific AppKit window-device number when available. Emit a usable windowId only through a separately justified mapping from that live native object to its current WindowServer window, validated against the same process incarnation's current inventory; record the mapping method and evidence. Same-process numeric equality, matching titles, bounds, or ordering alone cannot establish that identity. The mapping mechanism and its platform-specific proof must be settled before implementation approval. Some WindowServer windows genuinely have no native match, and some native windows have no WindowServer match; retain those records without inventing the other's identity. A proven ID can be passed unchanged to native tree, AX tree, screenshot, and correlation. Reject a mapping that becomes stale or ambiguous rather than rebinding it to a replacement window.

For example, ui windows TARGET --session SESSION supplies a verified window ID for ui view tree TARGET --session SESSION --window ID, ui ax tree TARGET --session SESSION --window ID, and ui screenshot TARGET --session SESSION --window ID --out image.png. Only the native tree evaluates the native graph; the capture still reads the same backing store through the existing capture path. None activates or redraws the target to make the other observations succeed.

existing connects only to a compatible Recon helper already present in the selected process; it never loads a new image. launch starts a non-running selected app with the helper explicitly enabled. It refuses an already-running target rather than activating it, replacing it, or manufacturing a fresh instance behind the caller's back; --pid is invalid with this mode. attach loads the helper into a selected running process without terminating or relaunching it. There is no automatic mode fallback and no --replace in this proposal.

The standard profile uses existing cooperation, signing, and debugger permissions and prepares nothing; it serves cooperative and supported targets. Operations that require the research profile — attaching the loader to a non-cooperative third-party target or a first-party/platform-binary target — are rejected under the standard profile and on an unprepared host, with an access-prerequisite failure that names the missing requirement and the recon ui session prepare-host command. The research profile runs those attempts only on a host the operator has prepared: for a platform-binary or first-party target it requires SIP and AMFI disabled and a Recon inspector signed with com.apple.private.thread-set-state, which the kernel honors only because AMFI is off. That path is proven (TextEdit and Music) but is explicitly research-only and not a shippable posture; on a stock machine AMFI rejects the entitlement and the attempt fails.

Host weakening is an explicit, opt-in operator action through recon ui session prepare-host, never a side effect of any inspection command. That command discloses exactly what it changes and why, then sets only the boot-args Recon can set (amfi_get_out_of_my_way=0x1 -arm64e_preview_abi tss_should_crash=0) through sudo nvram after confirmation and instructs a reboot; it also prints the exact operator steps to disable SIP in recovery, which Recon cannot perform itself and never hides or sends the operator elsewhere to learn. No inspection command disables SIP/AMFI/library validation, changes boot arguments, re-signs a target, installs an elevated service, invokes sudo, supplies administrator credentials, or grants TCC access; those host effects belong only to the deliberate prepare-host action. Neither profile overrides target identity, peer authentication, architecture, or protocol checks. If a selected mechanism can still request debugger authorization, preflight names that possible effect and open requires an explicit --allow-authorization flag before permitting the request; without it, return an access-prerequisite failure without a dialog. Denial never triggers escalation or retry under another identity.

--allow-authorization is accepted only with --mode attach; using it with existing or launch is a usage error. It permits only the selected mechanism's disclosed macOS debugger-authorization interaction, not elevation, security reconfiguration, target signing, or an alternate identity. If the backend cannot guarantee a no-dialog attempt without the flag, refuse before invoking that operation and report the unresolved authorization prerequisite. That no-prompt boundary must be demonstrated when selecting the loader.

Preflight reports bundle/process/architecture facts, helper availability and compatibility, observed signing/entitlement/protection facts, and per-mode eligible, blocked, or unknown with reasons and evidence sources. Static facts establish eligibility, not successful attachment. Inaccessible facts are unknown, not false. It is valid to succeed with a report that every mode is blocked; an unresolvable or ambiguous target still uses the existing targeting error contract. No system-wide “research ready” Boolean substitutes for target-specific evidence.

2. Session identity, trust, and lifecycle ​

A successful open returns the exact bundle path/id, PID plus independently checked process-incarnation identity, OS/build and target architecture, random session identifier, actual access mode/profile, helper build identity, wire protocol version, capabilities, and effects performed. Success requires an authenticated target-side handshake and bounded identity read, not a socket appearing or an injection API reporting success. Verify the selected process again across the open race; PID reuse or a changed executable cannot redirect a session.

Attachment must bind the loader to the verified process incarnation before the first target-side effect, using a stable kernel process/task identity rather than an unchecked numeric PID. Revalidate the selected incarnation and executable against that binding before loading or writing target memory. A post-load handshake is necessary but cannot repair injection into a replacement process. If a loader cannot provide this pre-effect binding, it is not eligible for this contract; repeated PID lookups before and after injection are not an equivalent guarantee. Controlled exit/PID-reuse races must demonstrate refusal without modifying the replacement target.

Use a local-only channel with kernel-backed peer identity checks and an unguessable per-session capability. A filesystem endpoint, if used, lives in an exclusively created owner-only directory with owner-only endpoint/descriptor permissions; do not trust or unconditionally unlink a predictable /tmp/<pid> path. Bind the handshake to the expected process incarnation, helper build, session nonce, and owning user. Do not emit capability secrets in command lines, output, or logs. Same-UID processes able to read the owner's files or memory are not promised an adversarial isolation boundary; the protocol still rejects unauthenticated, wrong-process, and cross-session requests. No network listener or arbitrary-code endpoint is introduced.

Only matching supported protocol/helper builds may communicate. A mismatch fails explicitly; it does not silently replace resident code, downgrade behavior, or activate an older compatibility path. existing or attach may reuse a still-valid session for the same process, profile, and build, returning reused: true without injecting again. Return the new request's mode separately from the mode that originally established the session; connecting with existing does not rewrite a prior launch into a different acquisition history. A profile/build conflict fails rather than upgrading the session. launch always refuses a running target, even if it already has a session. A process may have successive sessions, but only one active Recon session at a time in this proposal.

Helper residency and session lifetime are separate. A resident helper keeps an authenticated, local-only bootstrap endpoint and an owner-private discovery descriptor until process exit, even when no inspection session is active. Bootstrap permits only identity/compatibility negotiation, session-state reconciliation, and session establishment/revocation; it cannot read native objects. ui session open --mode existing verifies the descriptor's ownership, live process incarnation, and kernel-backed peer identity before establishing a new random session capability and empty handle namespace. Session close revokes every previous capability and handle without destroying this bootstrap path. One transport may serve both roles, but an inactive helper rejects every native operation until a newly authenticated open; stale descriptors or capabilities cannot reopen a session automatically.

Native handles are opaque session-scoped identities for windows, views, layers, cells, and referenced layout guides. A structural path is optional descriptive location, never the identity used for later reads. Maintain weak object identity without retaining the inspected graph for the life of the session; temporarily retain a resolved live object for the bounded read. Reordering, reparenting, or property changes preserve a surviving object's handle. Deallocation or replacement makes its old handle stale, even if the address, class, frame, or child index is reused. Closing/reopening a session, process exit, or relaunch invalidates every old handle. Never resolve a stale handle by searching for a similar replacement.

The registry has a 100,000-live-handle ceiling; remove dead weak entries, never recycle identifiers within a session, and report registry exhaustion as unavailable capacity rather than evicting a live object into a silently different identity. Historical observations remain readable JSON after handles expire; this does not implement #23's evidence store.

Close revokes the session capability, ends its inspection channel, drops registry state, and removes only its session-owned endpoint/descriptor, if separate from bootstrap. It leaves the target running and reports the resident helper and bootstrap endpoint separately from the closed session. No safe dlclose is promised for a library that registered Objective-C classes or otherwise joined the runtime. Acknowledged close and an already-closed locally known session are distinguishable successful results. A missing acknowledgment or transport failure is an unknown teardown outcome, not invented success. Process exit invalidates both bootstrap and session access; a later command can remove a stale local descriptor only after verifying its ownership and incarnation. There is no automatic reattachment.

An unacknowledged close enters close-unconfirmed locally. Retain the owner-private recovery descriptor and exact session/incarnation identity; never discard it and inject another helper. Refuse native reads and session reuse while revocation is uncertain. A repeated ui session close SESSION, or an explicit ui session open for that same process, first reconciles the named session through authenticated bootstrap state. Confirmed revocation or confirmed process exit resolves the uncertainty. If the old session remains active, repeat close explicitly; open returns INSPECTION_BUSY with that recovery action rather than reusing it. Unreachable bootstrap preserves the unknown outcome and refuses a replacement session. Reconciliation must not evaluate target UI properties or equate a missing local file with revocation.

3. Native structure and field semantics ​

Window enumeration includes native class, title/identifier when available, frame, visibility, key/main facts, content-view reference, child-window and sheet relationships, and the native window number where assigned. A missing number is not replaced by an ordinal. Enumerate each window once, retaining observed relationship/order information; a titleless, hidden, off-Space, or child window is not discarded merely for being inconvenient to correlate with WindowServer.

A view traversal begins at the requested view, the content hierarchy of a requested window, or each window's content hierarchy when no root is supplied. Each window record also exposes the topmost view reachable through that content view's same-window superview chain, when distinct, so an explicit root query can inspect AppKit's frame/chrome realization. Do not force a missing content view, load a controller's uninstantiated view, or create windows to fill the result. Preserve subviews order and real runtime class/superclass names, including private and KVO subclasses. Model NSControl.cell as a related cell, not a subview; layout guides and constraints are also relationships rather than fabricated visual children.

Layer traversal reads model-layer containment independently through sublayers. A view root selects its existing associated layer; no associated layer is a known absent relationship and a successful empty layer result. Never set wantsLayer, call makeBackingLayer, or force drawing/layout to obtain more data. Preserve layer identity when a layer is referenced from both a view and a layer relationship; a mask is a distinct relationship, not an invented sublayer. Report repeated references and cycles without recursively expanding them. Presentation-layer state and animation tracing are not included; results explicitly say layerState: model.

For --kind layer, a window root or --window selects the already-existing content view's associated layer. Missing content view or backing layer is a reported absent relationship and a successful empty scope; it never causes view creation or a switch to a different window.

The default field set is basic. --fields is a comma-separated, non-empty set of the following groups; unknown or repeated groups are usage errors. Identity, kind, relationships needed to interpret the returned structure, and completeness metadata are always present. No group is fetched merely to discard it later.

appearanceEffective appearance, supported control/text/background colors, and NSVisualEffectView material, blending mode, state, and emphasis. Retain named/catalog color identity when present alongside an explicitly identified resolved color space/components; unsupported conversions are visible.

A field known absent, unsupported for that object, denied, failed, or non-finite has an explicit per-field status. Unrequested fields are absent without a status. Preserve legitimate zero, false, and empty values. The response schema defines each group's typed values and status vocabulary; errors do not masquerade as empty values. Typed allowlisted AppKit access replaces arbitrary selectors, KVC paths, description, property enumeration, or generalized invocation. This still executes possible overrides; command effects must disclose that fact. Exceptions can become field failures only where a safe exception boundary exists; a crashed target is a failed observation, never a partial success assembled from guessed values.

Frame and bounds carry their coordinate space and units. View frame means its superview's logical points, with that coordinate system's orientation recorded separately from the view's own isFlipped. Window frames use AppKit global-screen logical points. Include a window-relative and global-screen normalization only when it can actually be computed, together with the display/scale transformation used. Do not multiply all values by a presumed Retina scale or equate model-layer geometry with current on-screen geometry.

Mark recognizable SwiftUI hosting boundaries with the evidence used to recognize them and swiftUIContent: not-inspected. Runtime names and native descendants remain useful evidence, but a substring match alone is a heuristic, not proof of a recovered SwiftUI view type. No AttributeGraph walk or declarative hierarchy is implied.

The font inventory groups identical observed font descriptors and lists contributing object handles and source kinds, including bounded attributed-run ranges without exporting text content. Traversal coverage and run limits accompany the inventory; a partial walk produces a partial inventory, not an exhaustive list of fonts rendered by the application. General text extraction, image bytes, and layer contents are not default outputs of this feature.

4. Bounded execution and observation results ​

New native/session-backed operations validate the session and request before AppKit work. Traversal and object-specific reads run on the target main thread; host-side decoding/projection/serialization uses copied observation values, not live pointers. The helper receives the requested root, filters, field groups, and bounds. It must not inspect an unrelated window forest or every rich field merely because the CLI will later filter it. Existing unbound WindowServer, AX, and screenshot operations retain their documented bounds and output contracts.

Tree/find/font traversal defaults to depth 3 and 200 returned records. Depth ranges from 0 through 64; limit ranges from 1 through 25,000. A selected root is depth zero; in the default view forest each window content root is depth zero and window metadata is outside view depth. Layer depth is relative to its selected layer root. The hard work ceiling is 25,000 visited objects/relationships per request across windows, views, layers, constraints, and attributed runs, with at most 256 runs examined per text carrier. Window nesting consumes the same request budget. Requested limits and hard limits both constrain target work, not just printed rows. A find limit stops after enough matches, with the unsearched scope identified; it never reports a full match count it did not compute.

Cap each request at 64 KiB and each complete response at 8 MiB; cap each returned string at 4,096 Unicode scalars and mark any truncation. Enforce framing/allocation limits before trusting lengths supplied by either endpoint. The same bounds apply to nested layers and field arrays; wide or cyclic graphs cannot bypass them. A valid smaller result identifies exactly which requested scope was narrowed and which reads were incomplete, using separate narrowed and truncated reasons rather than one ambiguous flag.

Use a two-second native-read deadline covering queueing, target execution, transport, and response delivery, and a ten-second open/close deadline. A queued native read whose deadline expired must not begin later. Check the budget between individual reads; never kill the target or asynchronously unwind its main thread to enforce it. A getter already executing when the deadline expires may continue or remain blocked. Return a timeout with its stage and targetExecutionMayContinue: true when appropriate; do not claim rollback, cancellation of target code, or a coherent result. Allow only one outstanding helper UI read per process incarnation, not merely per session. After an unresolved execution timeout, refuse new helper UI reads until that work actually finishes or the process exits. Close may revoke access, but closing/reopening does not clear the in-flight guard or imply target execution stopped. A new session reports native inspection as busy until the old work completes; its old response cannot become a result for the new session. Lifecycle/transport handling remains separately responsive where possible. External AX/capture retain their own execution/timeout contracts after optional session validation; they do not pass through the helper's AppKit read queue.

Native observation components include application/process incarnation, session/helper/protocol identity, source native-appkit, requested scope/fields, unique observation id, start/end times, OS/build/architecture, and explicit coverage. Their consistency claim is main-thread, best-effort observation over that interval—not an atomic snapshot of the whole application or compositor. Joined/correlated responses preserve each component's source and interval; optional session binding does not relabel external AX or WindowServer capture as native AppKit evidence. An empty fully observed scope is distinguishable from an unavailable target. Preserve one JSON object on stdout and the existing typed error envelope on stderr; no helper logs, JSON-Lines footer, or raw target output contaminate that contract.

5. Shared UI integration, no-focus behavior, and AX correlation ​

ui correlate captures native and external AX evidence separately for the same verified process incarnation and selected WindowServer window. Resolve the native window through the shared --window contract; a missing real match is an explicit unavailable correlation, never a title guess. Record independent observation ids/times, coordinate transformations, and completeness for both sides. Native object handles and AX snapshot paths remain different identifiers. The composite query budgets both reads and reports either source's incompleteness; it does not reuse a historical observation as if captured simultaneously.

Candidate matches use a non-empty exact accessibility identifier observed on both interfaces where available; otherwise they require matching self-reported AX role and normalized screen bounds within one logical point on every edge. Native NSView.identifier is not silently treated as accessibilityIdentifier. Retain every candidate when ambiguous. Record the matching basis; even a unique candidate is not asserted to be the same underlying object. Unmatched nodes are a difference between evidence sources, not an automatic accessibility defect or an instruction to synthesize a node. In-process accessibility getters are marked as target-executed reads, not substitutes for the external AX capture.

External AX acquisition reuses Recon's existing privacy identity and permission behavior under decision.0002. Failure to obtain the required observation fails correlation with its typed cause; it does not disable independent native queries. A target-loaded helper does not inherit Recon's host-side grants or substitute for the external AX capture.

One no-focus contract ​

After required permissions/setup are established, every ui operation must respect the user's foreground work, including operations under ui ax, ui view, and ui session. Recon must not activate or raise the target, transfer system keyboard focus, make a target window key as an enabling step, switch Spaces, warp the real pointer, or redirect/suppress the user's input. This applies to native reads, external AX/window reads, screenshots, session connection/teardown, and supported explicit UI actions; it is not a property reserved for the old winctl-derived commands.

“Focus without raise” still steals keyboard focus. Activate-then-restore, cursor-move-then-restore, switching Spaces to inspect a window, and temporarily focusing a control to make input work all violate the contract. Never use them as hidden retries or fallbacks. A mechanism that cannot perform the requested operation within this boundary is unavailable; fail with its typed reason rather than degrading to desktop automation or pretending an empty result is complete.

Observation remains strictly read-only: no clicks/keys, AX actions or attribute writes, responder changes, opened menus, layout/display flushes, drawing, or forced layer/view creation. ui session open --mode launch is an explicit lifecycle effect, not an implicit read prerequisite: use background startup without requesting activation, and require no-focus evidence for the supported launch path. Do not focus the app once to “prime” later inspection. This does not change the separate, explicitly activating app launch command. Launching an application and activating it must remain separately described effects, not assumed synonyms.

Explicit UI interaction changes the intended target state, not the user's desktop focus. #24 implements those actions under ui using the same bundle/instance/window selection and privacy machinery. No injected session is required when the supported out-of-process mechanism suffices; a supplied session is an identity assertion, not permission to invoke arbitrary code. AX action, target-routed mouse input, and process-directed keyboard input are different mechanisms and must be identified honestly. Correlation candidates and historical AX paths are not automatically executable targets. An action must freshly validate its actual target/window; if it cannot honor --window without changing focus, reject that request rather than ignore the selector or target the current key window. A successful event post is not a claim that the requested control action occurred. Implementing #24 remains separate work; sharing its contract does not make it a prerequisite for inspection.

Target-internal responder changes that are the intended consequence of an explicit action are not the same as moving the user's system keyboard focus. Native getters and actions nevertheless execute application code, which may itself activate a window, open UI, block, or crash. Recon cannot prove arbitrary target code pure. Known activation-dependent operations are unsupported in the no-focus path; a detected unexpected interference is a failed operation with observed effects, not a successful no-focus result merely because Recon made no direct activation call. Stop further steps, do not retry automatically, and do not steal focus back as “rollback.” An unexplained concurrent user action must not be falsely attributed to the target.

Explicit setup exception ​

Mark chose to retain decision.0002: when a required privacy grant is missing, the existing path may request macOS authorization and then fails with PERMISSION_DENIED. Those OS dialogs can interrupt the desktop, so the no-interruption guarantee is explicitly conditional on prerequisites already being established. context and ui session preflight still never request grants; callers can inspect prerequisites first. Debugger authorization still requires ui session open --mode attach --allow-authorization. Neither exception authorizes activating the target, altering TCC directly, changing protections, or silently continuing after a missing prerequisite.

Registry metadata and guides must distinguish target-code loading, background application launch, target-getter execution, capture/file writes, and applicable privacy/debugger prompt effects. The active CLI's explicitly activating app launch remains separately advertised. A setup exception must not be described as a harmless read, and an explicit action must not be described as observation. Sharing command names must preserve these effect and permission distinctions.

6. Failures and required verification ​

Reuse existing selection/usage/host/privacy errors where their meanings still apply. Add closed, schema-published native classifications rather than repurposing the current AX-specific TIMEOUT: INSPECTION_UNAVAILABLE (including unsupported target ABI/build or missing access prerequisites), INSPECTION_PROTOCOL_MISMATCH, INSPECTION_FAILED, INSPECTION_TIMEOUT, INSPECTION_BUSY, STALE_SESSION, and STALE_NODE. Native failures identify the stage, target/session where known, observed cause, and whether target execution or helper residency may remain. Malformed handles/options are INVALID_ARGUMENT; a well-formed expired identity is stale. Do not mark an uncertain execution timeout or failed attach as automatically retryable. Read or close failures never become a successful empty tree or a fictitious teardown acknowledgment.

Add the shared UI_INTERFERENCE classification for detected violations of the no-focus contract, distinct from a preflight INSPECTION_UNAVAILABLE that prevents a known-unsafe native operation. Its details identify the stage, evidence source, affected process/window where known, observed disturbance, and whether target execution/effects may remain; it is not automatically retryable. Existing out-of-process operations retain their appropriate unavailable-interface/permission classifications, not a fabricated native-session prerequisite.

Implementation evidence must cover these six coherent outcomes:

  1. Access: A real helper handshake and native read through Recon for cooperative launch, an already-present helper, and permitted live attach. On an operator-authorized, already-configured research Mac, also prove a same-user non-cooperative third-party target and a protected Apple AppKit target, including an arm64e case. Record exact target/OS/helper/loader/signing/security conditions. A denied attempt on a stock Mac is not the research success case.
  2. Lifetime and trust: Exit/relaunch/PID reuse, two installed app copies, peer/process/protocol mismatch, close acknowledgment loss, same-session sibling reorder/replacement, deallocation/address reuse, and reconnect never alias a new target or object. Verify pre-effect loader binding prevents injection into a replacement process. Close leaves the target alive and reports residual code honestly; lost acknowledgments retain recoverable uncertainty until authenticated reconciliation.
  3. Structure and facets: Controlled fixtures provide native-only views, a custom/private subclass, a cell, child windows/sheets, independent sublayers and masks, controlled absent layers, named/dynamic colors, fonts and attributed runs, ancestor-owned constraints, layout guides, and SwiftUI hosting. Oracle-owned values are exact; OS-private class spelling and incidental layer creation are observations, not pinned implementation tests.
  4. Bounds and effects: Exercise zero depth, projection that does not evaluate excluded getters, repeated/cyclic relationships, wide graphs, oversized frames, malformed input, busy main thread, an expired queued request, and a deliberately blocking/throwing getter. No delayed queued read executes after cancellation; closing/reopening cannot bypass an already-running getter's process-wide guard. Across native and AX reads, capture, session lifecycle, and background launch, use a controlled foreground app/responder and event traces to verify no transient activation/focus/Space changes, no real pointer movement, and no diverted input. Before/after PID equality alone cannot prove this. Cover background, secondary/non-key, occluded, minimized and off-Space windows with exact supported outcomes; unavailable cases must not trigger focus-changing fallback. Verify an intentionally interfering fixture is not reported as a successful no-focus operation. Exercise setup prompts separately from this no-focus matrix. #24 must later prove action-specific delivery and actuation against the same boundary, rather than inheriting a universal input claim from winctl.
  5. Compatibility ​

This is a deliberate command migration, not an entirely additive family. Existing ui windows and ui screenshot behavior remains available without a session; the optional session binding adds no implicit injection or activation. Move the existing AX-only ui tree grammar and output semantics to ui ax tree, including depth/menu narrowing and window selection. Native queries use ui view and require --session. Retire ui tree entirely, with or without a session option; do not reuse it for another representation. No top-level ax, standalone native, compatibility aliases, automatic source selection, or AX-to-native fallback remains. Earlier draft spellings were never shipped and need no compatibility path.

Migrate every maintained caller, live guide, example, fixture invocation, command/error/schema reference, and contract test from the old AX spelling to ui ax tree; include schema ui ax tree, schema ui view tree, and the ui session leaves. Group help and schema discovery must expose the nested structure, and resolved command metadata and failure recovery must name the complete path rather than flattening it or dropping ax, view, or session. Extend the existing registry/parser/discovery contract to represent these groups; do not create a parallel command catalogue or hand-written help hierarchy. Preserve historical implemented proposals as records of their shipped revisions and document the migration here and in the current CLI guide. app and context retain their existing meanings and privacy identity. New effects/errors and conditional session-enriched schemas belong to that same registry. There is no stored-data migration, mismatched-helper wire-compatibility promise, or dependency on #23's unfinished persistence service.

The proposal does not require every native consumer to wait for this view inspector: #51's access/identity/lifecycle outcome remains separately verifiable for #13/#45/#48/#50. This proposal does not implement those consumers, or Simulator/device sessions #52/#53.

Implications on adoption ​

Users migrate AX scripts from ui tree to ui ax tree, keep window enumeration/capture under ui, and use ui view for native visual inspection. Explicit inspection access is under ui session; install a matching CLI/helper build only for session-backed inspection. Native reads require an explicitly opened session and never upgrade an AX request into injection. Package the Recon-owned loader and helper with the preview; do not download code dynamically during inspection or require Frida. Record artifact provenance, applicable source notices, and verified architectures.

Cooperative targets retain their own signing/cooperation requirements; Recon does not alter another app to make it eligible. Research users prepare and authorize a macOS 27 machine — SIP disabled in recovery by the operator and the Recon-set boot-args applied through recon ui session prepare-host — and accept the target-execution risk. No new hardware, service, certificate, or paid resource is authorized by this proposal. Closing a session revokes inspection access but may leave code mapped until the app exits; callers decide whether and when to restart their application.

Scope ​

  • The #51 macOS session outcome and the #44 native view/layer outcome, delivered together with real cooperative and research-machine evidence.
  • Target-specific preflight, explicit modes/profiles, authenticated local communication, process/session/object lifetime, and truthful cleanup.
  • Native windows/views/cells/layers, supported visual/layout/font facets and inventory, bounded search and drill-down, SwiftUI boundaries, and separate AX correlation through shared window selectors.
  • The nested ui ax/ui view/ui session command organization and AX migration, registry/schema/errors and maintained callers, shared no-focus requirements, controlled fixtures, user guides, private preview, and the verification above.
  • Two access profiles — standard (cooperative/supported targets) and research (non-cooperative third-party and first-party/platform-binary targets) — with research-only operations rejected under the standard profile or on an unprepared host; first-party injection proven on TextEdit and Music.
  • recon ui session prepare-host: explicit, opt-in host preparation that sets the boot-args Recon can set, reports prerequisite status, reverts its own boot-args, and prints the exact operator steps to disable SIP in recovery, which Recon cannot perform itself.

Out of scope ​

  • Weakening protections as a side effect of inspection, or disabling SIP (Recon cannot, and instead prints the exact operator steps); changing another app's signature/entitlements, installing an elevated daemon, acquiring credentials, or claiming access to every protected target. Explicit, disclosed host preparation through recon ui session prepare-host is in scope and is the only place Recon alters host security.
  • A read-only external memory-inspection path for first-party targets; first-party inspection is injection-only under the research profile.
  • Intel, Rosetta targets, older macOS, UIKit/Catalyst, Simulator, physical iOS devices, Windows, and Android; none is silently counted as covered by an Apple-silicon Mac test.
  • General class/heap/ivar exploration (#45), arbitrary method invocation or state edits (#49), network hooks (#48), resource bytes (#13), application-local state (#50), and implementation of new UI actions (#24). The shared targeting/no-focus contract applies to the action design; keeping action implementation separately scoped does not create a disconnected UI system.
  • SwiftUI value/AttributeGraph reconstruction, presentation-layer/animation tracing, a complete Auto Layout solver explanation, live event streaming, remote control, a plugin SDK, or an external scripting shell.

Future directions ​

The separately tracked runtime, network, asset, and application-state inspectors may reuse the session contract without sharing this view walk; their future CLI entry points are not prescribed here. UI interaction (#24) belongs under ui, reuses this targeting/no-focus boundary, and remains usable through supported out-of-process mechanisms without mandatory injection. Catalyst (#55) and UIKit Simulator/device work (#40/#41, #52/#53) reuse the representation and session concepts only after their own access, identity, and lifecycle evidence; a shared namespace is not proof of platform support. DOM and deeper declarative UI inspection remain separate representations, not invented descendants in an AppKit tree. Broader OS/architecture coverage, animation state, and deeper SwiftUI research are independent changes. None replaces the research-machine access already required here.

Open questions ​

  • RESOLVED. The loader is Recon-owned (no Frida): one task_for_pid control port; TASK_AUDIT_TOKEN PID+pidversion incarnation binding verified before any effect; dyld shared-cache UUID/slide agreement check; mach_vm_write/mach_vm_protect bootstrap; pthread_create_from_mach_thread + dlopen/dlsym; arm64e build with ARM_UNIFIED_THREAD_STATE + thread_convert_thread_state(FROM_SELF) for the PAC entry. Proven on cooperative get-task-allow fixtures (arm64e→arm64e, arm64e→arm64, arm64→arm64) with wrong-token and post-exec stale-port rejection and no leaked effect, and on a non-cooperative hardened third-party-class fixture. First-party/platform-binary Access is also proven on the operator-prepared research host: signing the inspector with com.apple.private.thread-set-state (honored under AMFI-off) releases the THREAD_SET_STATE guard, giving full injection and a live NSApp.windows read on TextEdit (flags=0x0) and Music (flags=0x12000, hardened + library-validated). That path requires the operator-weakened host (SIP+AMFI off) and is research-only, not shippable.
  • RESOLVED. Native inspection runs in-process, so native window identity is the live NSWindow reachable from NSApp.windows; the CGWindowID --window is correlated to it in-process via NSApplication.window(withWindowNumber:) with owner-PID equality and NSApp.windows membership. Proven on a fixture, including rejection of a wrong window's id, an overridden public windowNumber getter not fooling the mapping, and a deallocated window's old id resolving to nil. Hidden versus closed-but-retained windows are indistinguishable through public CGWindowList metadata, so such matches are reported unavailable rather than guessed; the required shared selector and correlation outcome is preserved for the visible-window case.
